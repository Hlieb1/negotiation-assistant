# Модуль прийняття рішень

Код: `server/app/decision/`. Правила: `server/rules/fuzzy_rules.txt`. База реплік: `server/app/decision/replies_uk.json`. Промпт мовної моделі: `server/app/decision/llm_prompt_uk.json`.

## 1. Спільний інтерфейс

```python
DecisionModule.decide(state: StateVector, voice_features: dict, transcript: str,
                      history: list[Decision]) -> Decision
```

- `StateVector` — переговорний стан з етапу 4: назва, ступені 5 станів, упевненість, валентність, збудження, вагання.
- `voice_features` — відхилення просодії від норми мовця (z-оцінки гучності, тону, розкиду тону, темпу, пауз).
- `transcript` — остання розпізнана фраза співрозмовника (якщо вона не старша за 6 с).
- `history` — останні 5 рішень (щоб не повторюватися).
- `Decision` — репліка, тон, упевненість, джерело (`fuzzy`, `llm`, `hybrid`, `llm_fallback`, `hybrid_fallback`), стратегія та службові деталі.

Модуль не залежить ані від мережі, ані від клієнта. Протокол WebSocket з'являється лише в `app/hint.py`, де `Decision` перетворюється на повідомлення `hint`. Тому той самий модуль можна використати в роботі-переговорнику без змін.

## 2. Коли формується підказка (`app/hint.py`, `HintPolicy`)

Підказка надсилається, лише якщо виконано всі умови:
1. переговорний стан змінився порівняно з останньою підказкою;
2. новий стан тримається щонайменше `decision.stable_s` = 1 с (захист від «миготіння»);
3. від попередньої підказки минуло щонайменше `decision.min_interval_s` = 4 с;
4. упевненість не нижча за `decision.min_confidence` = 0,1.

## 3. Варіант А — нечітка логіка (`fuzzy.py`, scikit-fuzzy)

### Вхідні лінгвістичні змінні (0…1)

| Змінна | Терми і функції належності |
|---|---|
| ступінь кожного стану: anger (злість), tension (напруга), doubt (сумнів), agreement (згода), neutral (нейтральний) | низький — трапеція (0; 0; 0,1; 0,25); середній — трикутник (0,15; 0,3; 0,5); високий — трапеція (0,35; 0,6; 1; 1) |
| confidence (упевненість) | низька — трикутник (0; 0; 0,35); висока — трапеція (0,2; 0,6; 1; 1); будь-яка — стала 0,2 |

Ступені 5 станів у сумі дають 1, тому «високим» уже вважається ступінь від 0,35–0,6.

### Вихідні змінні

| Змінна | Терми |
|---|---|
| активація кожної стратегії: calm (заспокоїти), argue (аргументувати), clarify (уточнити), close (закріпити домовленість), pause (пауза) | слабка — трикутник (0; 0; 0,5); сильна — трикутник (0,5; 1; 1) |
| tone (тон) | м'який — (0; 0; 0,5); рівний — (0,25; 0,5; 0,75); впевнений — (0,5; 1; 1) |

Виведення за Мамдані (min для AND, max для OR та агрегації), дефазифікація методом центру ваги. Обирається стратегія з найбільшою активацією. Тон: < 0,42 — м'який, > 0,58 — впевнений, інакше рівний.

### Вибір репліки

`replies_uk.json` містить по 5 реплік на кожну стратегію і словесні описи тону. Репліка вибирається випадково серед тих, яких не було в останніх 3 підказках.

### Перевірка на типових станах

| Ситуація | Упевненість 0,15 | Упевненість 0,5 |
|---|---|---|
| злість | заспокоїти / м'який | заспокоїти / м'який |
| злість + напруга | заспокоїти / м'який | заспокоїти / м'який |
| напруга | заспокоїти / м'який | заспокоїти / м'який |
| напруга + сумнів | уточнити / м'який | уточнити / м'який |
| сумнів | уточнити / рівний | уточнити / рівний |
| легкий сумнів | аргументувати / рівний | аргументувати / рівний |
| згода | закріпити / впевнений | закріпити / впевнений |
| згода + сумнів | уточнити / рівний | аргументувати / впевнений |
| нейтральний | аргументувати / рівний | аргументувати / рівний |
| розмитий стан | аргументувати / рівний | заспокоїти / м'який |

## 4. Варіант Б — локальна мовна модель (`llm.py`, Ollama)

- Модель `qwen3:8b` через HTTP API Ollama (`/api/chat`), режим міркувань вимкнено (`think: false`), температура 0,6, до 100 токенів.
- Системний промпт українською (ролі, правила поведінки для кожного стану, заборона вигадувати факти, формат відповіді) і 3 приклади (злість, сумнів, згода).
- Опис ситуації: стан і ступені, впевненість, словесний опис голосу з z-оцінок («говорить голосніше, ніж зазвичай», «робить багато пауз»), остання фраза співрозмовника, 3 попередні підказки.
- **Формат** задається JSON-схемою (`format` в Ollama): `{"reply": str, "tone": str}`. Відповідь перевіряється (pydantic): репліка 3–240 символів, тон 2–80.
- **Таймаут** `decision.llm.timeout_s` = 4,5 с. Якщо модель не встигла, відповіла не за схемою або сервер недоступний, повертається рішення варіанту А з позначкою `llm_fallback`.
- **Прогрів:** під час старту сервера модель обробляє системний промпт із прикладами. Ollama кешує цей префікс, тому подальші запити обробляють лише опис ситуації.

## 5. Гібрид (`hybrid.py`)

Стратегію й тон визначає варіант А, а текст репліки генерує мовна модель з обов'язковими стратегією і тоном у запиті. Тон у підсумковій підказці завжди береться з А. Якщо модель не встигла, використовується репліка з бази А (`hybrid_fallback`).

## 6. Порівняльний експеримент

Скрипт `server/evaluation/eval_decisions.py` проганяє 8 типових ситуацій (`scenarios_uk.json`: 2 × злість, напруга, 2 × сумнів, 2 × згода, нейтральний) через три режими й зберігає CSV з репліками, тоном, часом і часткою запасних відповідей. Цей CSV — основа для анкети експертів (етап 7).
