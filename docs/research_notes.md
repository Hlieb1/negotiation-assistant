# Журнал спостережень і результатів

Робочі нотатки для розділів диплома: рішення, виміри, проблеми та їх розв'язання. Записи додаються після кожного етапу.

| Компонент | Значення |
|---|---|
| Процесор | Intel Core i7-14650HX |
| Оперативна пам'ять | 32 ГБ |
| Відеокарта | NVIDIA GeForce RTX 5060 Laptop GPU, 8 ГБ (драйвер 591.91, CUDA 13.1) |

## Етап 0. Вибір моделей під обладнання

### Мовна модель (модуль рішень, варіант Б)

- Обрано **qwen3:8b** (квантування Q4_K_M, 5,2 ГБ на диску). Модель повністю розміщується у відеопам'яті: 5,6 ГБ, 100 % GPU, контекст 4096 токенів.
- Запасний варіант — gemma3:4b, якщо затримка перевищить 5 с. MamayLM (україномовна) — кандидат для порівняння якості української.
- Виміри на запиті з відповіддю одним реченням українською, формат JSON, режим міркувань вимкнено (`think=false`):

| Показник | Значення |
|---|---|
| Перший запит (холодний старт, завантаження моделі в пам'ять) | 115,5 с |
| Повторний запит («теплий») | 4,8 с |
| Швидкість генерації | 16,9 токен/с |

- Висновок: для вимоги «до 5 с для варіанту Б» модель треба завантажувати під час старту сервера (прогрів) і обмежувати довжину відповіді.
- Якість: відповідь граматично коректна українською, формат JSON дотримано.

### Розпізнавання мовлення

- faster-whisper, модель `small`, працює на GPU (float16). Моделі medium + LLM разом займали б близько 7 ГБ із 8, тому почато з small.

### Розпізнавання емоцій за обличчям

- TensorFlow на Windows не підтримує GPU, тому DeepFace працює на CPU. Для 3–5 кадрів/с цього достатньо (див. етап 2).

## Етап 1. Протокол і каркас сервера

- Транспорт — WebSocket, повідомлення JSON (опис у `docs/protocol.md`).
- Затримку `latency_ms` рахує сервер від моменту отримання даних до надсилання підказки, тому розбіжність годинників телефона й ноутбука на неї не впливає.
- Перевірка з тестовим клієнтом (вебкамера + мікрофон ноутбука, 12 с): отримано 44 кадри (~3,7 кадр/с) і 10 с аудіо; затримка підказки-заглушки 80–200 мс.

## Етап 2. Розпізнавання емоцій за обличчям

### Швидкодія детекторів облич (CPU, кадр 640×480)

| Детектор | Час на кадр | Примітка |
|---|---|---|
| opencv (каскади Хаара) | 35–47 мс | використовується за замовчуванням |
| yunet | ~14 мс | швидший, кандидат на заміну |
| retinaface | ~3800 мс | непридатний для реального часу на CPU |

### Порівняння класифікаторів емоцій

Методика: запис із вебкамери ноутбука за сценарієм. Учасник по черзі демонструє 6 виразів по 6 с: нейтральний, радість, злість, здивування, смуток, нейтральний. Аналізується 4 кадри/с. Перші 1,5 с кожного відрізка (зміна виразу) не враховуються. Детектор облич в обох випадках той самий (opencv), обличчя вирізається з полем 10 % ширини. Оцінено 108 кадрів. Скрипт: `server/evaluation/eval_face_recording.py`.

| Класифікатор | Навчальний набір | Точність | злість | радість | нейтр. | смуток | здивув. | Час на кадр* |
|---|---|---|---|---|---|---|---|---|
| DeepFace Emotion | FER-2013 | **29,6 %** | 0 % | 100 % | 0 % | 77,8 % | 0 % | 35 мс |
| HSEmotion enet_b2_7 | AffectNet | **77,8 %** | 100 % | 100 % | 33,3 % | 100 % | 100 % | 40 мс |

\* разом із пошуком обличчя.

Типові помилки DeepFace: нейтральне обличчя і злість визначаються як смуток (у середньому 0,96–0,98), здивування — як страх (0,91).

Інші моделі HSEmotion на тому самому записі (без пошуку обличчя, лише класифікація):

| Модель | Точність | Час на обличчя |
|---|---|---|
| enet_b0_8_best_afew | 69 % | 10 мс |
| enet_b0_8_best_vgaf | 67 % | 10 мс |
| enet_b2_7 | 79 % | 17 мс |

Спроби покращити DeepFace попередньою обробкою (не допомогли, нейтральне і злість так само → смуток):

| Варіант | Точність |
|---|---|
| opencv, вирівнювання обличчя | 29 % |
| opencv, без вирівнювання | 32 % |
| opencv, поле 20 % | 31 % |
| opencv + CLAHE | 31 % |
| yunet | 31 % |
| yunet, поле 20 % | 34 % |
| yunet, без вирівнювання, поле 10 %, CLAHE | 49 % |

Калібрування під людину (ділення ймовірностей на «базовий» вектор нейтрального обличчя, записаного на початку сесії) погіршило точність HSEmotion: 94 % без калібрування на відрізках 2–6, 89–60 % з калібруванням залежно від його сили. Від калібрування відмовилися.

**Рішення:** основний класифікатор — HSEmotion enet_b2_7. DeepFace лишається як варіант у `config.yaml` (`video.classifier`) для порівняння.

Обмеження експерименту: один учасник, одна сесія, бічне освітлення з вікна (одна половина обличчя затемнена), вирази стримані. Для диплома потрібна перевірка на більшій вибірці (етап 7).

### Згладжування

- Ковзне вікно 1,5 с, середнє ймовірностей по кадрах, де знайдено обличчя.
- Якщо обличчя є менш ніж на 30 % кадрів вікна — стан «обличчя не знайдено».
- Обмежувач частоти аналізу з допуском 20 % на нерівні проміжки між кадрами: до виправлення при 4 кадр/с від клієнта аналізувалося 51 з 77 кадрів, після — 57 з 59.

## Етап 3. Аналіз голосу

### Вибір класифікатора емоцій за голосом

- Пошук українського корпусу мовлення з розміченими емоціями (листопад 2026) не дав результату. Існують лише:
  - DRSSU — корпус реального та синтезованого українського мовлення, емоції лише в синтезованій (TTS) частині;
  - EmoBench-UA — емоції в українських текстах, не в аудіо;
  - корпуси для ASR/TTS (Common Voice та ін.) без розмітки емоцій.
- Навчання на англомовних акторських корпусах (RAVDESS, CREMA-D) відхилено: вимога — модель має працювати з українським мовленням.
- **Рішення:** готова багатомовна модель **emotion2vec+ large** (FunASR, Hugging Face `emotion2vec/emotion2vec_plus_large`). Модель попередньо навчена на великому обсязі мовлення різними мовами (самоконтрольоване навчання і дані з автоматичною розміткою емоцій); власного донавчання немає. Модель розрізняє 9 класів; 7 з них відображено на базові емоції системи, класи «other» та «unknown» відкинуто, а їхня сумарна частка зберігається як показник невизначеності.
- Перевірка точності — на власних українських записах за сценарієм (`tools/voice_demo.py --scenario`, оцінка — `evaluation/eval_voice_recording.py`), з порівнянням large і base.
- Ознаки голосу Librosa (тон F0, гучність, темп, паузи, MFCC) обчислюються окремо: вони потрібні модулю рішень і для опису тону співрозмовника, а не для класифікатора.

### Ознаки голосу

| Ознака | Як обчислюється |
|---|---|
| Частка мови, паузи | webrtcvad (кадри 30 мс, агресивність 2) + енергетичний поріг −45 дБ, утримання 3 кадри |
| Частка пауз | частка тиші між першим і останнім мовним кадром |
| Паузи за хвилину | паузи ≥ 0,2 с усередині мовлення |
| Тон F0 | `librosa.pyin`, 65–400 Гц: середнє (Гц), розкид і діапазон 5–95 % (півтони) |
| Гучність | RMS у дБ: середнє і розкид |
| Темп | кількість акустичних онсетів за секунду мовлення (наближення складового темпу) |
| Тембр | спектральний центроїд, 13 MFCC (середні) |

Шумоочищення — спектральне віднімання стаціонарного шуму (noisereduce) перед VAD.

### Перевірка на українському мовленні (перший запис)

Методика: один диктор (автор), мікрофон ноутбука, кімната. Дві ділові фрази («Давайте ще раз обговоримо умови договору.», «Ви пропонуєте саме таку ціну?»), кожна вимовлена з 6 емоціями за підказками на екрані; 12 записів по 5 с. Скрипти: `tools/voice_demo.py --scenario`, `evaluation/eval_voice_recording.py`.

| Модель | Шумоочищення | Точність | Час на запис |
|---|---|---|---|
| emotion2vec+ large | так | **50 %** (6/12) | 33 мс |
| emotion2vec+ large | ні | 42 % (5/12) | 97 мс* |
| emotion2vec+ base | так | 17 % (2/12) | 89 мс* |
| emotion2vec+ base | ні | 50 % (6/12) | 26 мс |

\* перший прогін після завантаження моделі, час не показовий.

По емоціях (large, з шумоочищенням): радість 2/2, смуток 2/2, тривога 2/2; нейтральне 0/2 (→ відраза, смуток), злість 0/2 (→ відраза, смуток), здивування 0/2 (→ відраза, страх). Нейтральної емоції модель не видала жодного разу.

Спостереження:
- Вибірка мала (12 записів, 1 диктор), різниця між варіантами в межах 1–2 записів; висновки попередні.
- Рівень сигналу низький: середня гучність мови від −43 до −31 дБ (мікрофон ноутбука на відстані).
- Зіграна «злість» акустично майже не відрізнялася від нейтральної: гучність −39,7 і −36,7 дБ проти −40,3 дБ у нейтральній, F0 113–129 Гц проти 111–148 Гц. Отже, частина помилок — через стриманість виконання, а не лише через модель.
- Як і для обличчя, модель зміщує спокійне мовлення в бік негативних емоцій (смуток, відраза). Це треба врахувати при об'єднанні (етап 4): вага голосу нижча за вагу обличчя, а «смуток/відраза» з малою впевненістю не вважати сильним сигналом.
- Whisper small на тихому сигналі часто спотворює слова («обовримо мову другу» замість «обговоримо умови договору»); на етапі 7 варто порівняти з medium.

Рішення: лишаємо emotion2vec+ large з шумоочищенням; для надійнішої оцінки потрібні додаткові записи (голосові повідомлення, інші диктори).

### Розпізнавання мовлення

- faster-whisper `small`, мова `uk`, GPU float16, beam size 1.
- Фрагменти по 2 с накопичуються у висловлювання; висловлювання завершується паузою ≥ 0,6 с або досягає 10 с і тоді передається на розпізнавання.

### Швидкодія (фрагмент 2 с)

| Крок | Час |
|---|---|
| Шумоочищення + VAD | ~420 мс (CPU) |
| Ознаки Librosa | ~80 мс (CPU) |
| emotion2vec+ large | ~22 мс (GPU) |
| Обробка фрагмента без мови | 26–31 мс |
| Завантаження і прогрів emotion2vec+ large | 49,6 с (вперше, разом із завантаженням 1,2 ГБ) |

Відеопам'ять: emotion2vec+ large ~0,6 ГБ; разом із whisper small ~1,4 ГБ (без LLM).

### Технічні проблеми та розв'язання

| Проблема | Причина | Розв'язання |
|---|---|---|
| Не працюють вікна OpenCV, немає `CascadeClassifier` | DeepFace і hsemotion-onnx встановлюють інші збірки OpenCV, які перекривають повну | після встановлення залежностей перевстановлюється `opencv-contrib-python` (`server/setup.ps1`) |
| Сервер падав при завантаженні ваг DeepFace | DeepFace друкує емодзі, консоль Windows (cp1252) не може їх вивести | вивід переведено в UTF-8 у `app/__main__.py` |
| OpenCV 5 не містить файлів каскадів Хаара | зміни в пакеті OpenCV 5 | DeepFace завантажує їх сам у `~/.deepface/weights` |
| Помилка `urllib.request` у hsemotion-onnx | бібліотека не імпортує модуль | модуль імпортується перед створенням моделі |
| Сервер Ollama не стартує з програми в треї | програма не дочікується, поки сервер знайде GPU | сервер запускається командою `ollama serve` |
| PyTorch для RTX 5060 | архітектура Blackwell (sm_120) потребує збірки з CUDA ≥ 12.8 | `torch 2.11.0+cu128` з індексу download.pytorch.org |
| FunASR засмічує лог сотнями рядків під час завантаження | модель пише в кореневий логер | на час завантаження рівень кореневого логера піднімається до WARNING |
